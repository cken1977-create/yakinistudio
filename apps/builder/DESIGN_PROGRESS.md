## Step 2: schema v2

- `SiteDoc` is version 2. It adds `style: { preset, surface, fontPair, radius, motion }` (plan 6.1),
  and `FONT_PAIRS` gains `signature` (Cormorant Garamond, Inter and JetBrains Mono; the files arrive in step 3).
- The v1 → v2 migration (`packages/site-schema/src/migrations/v1_to_v2.ts`, pure) gives every v1 doc
  `{ preset: 'classic', surface: 'light', fontPair: brand.fontPair, radius: 'round', motion: 'off' }`.
  An asterisk already in a v1 headline becomes U+2217 (∗), which looks the same and stays literal.
- New drafts: food-truck and restaurant start on `signature` (dark surface, signature fonts,
  subtle motion); the other kits start on `classic` (`packages/kits/src/index.ts` `defaultStyle`).
  `style` is the server's to set, like `brand`: the AI content schema has no `style`, and a
  submitted one is dropped.
- Accent marker: `headline` and every `heading` accept one `*phrase*` (a second marker or a lone
  asterisk is refused). The renderer outputs `<em class="ys-accent">`. `plainText()` strips the
  marker in the page title, the meta description (`metaFor`) and JSON-LD (the new `slogan`). The
  generate pipeline sends back any marker outside a headline.
- **Proof the old look is unchanged:**
  - `packages/sections/src/__snapshots__/v1-classic` holds the pre-v2 HTML of every v1 fixture
    page (live and draft). `migrate.test.tsx` requires the same markup after migration, apart from
    the two new root attributes and the JSON-LD slogan.
  - The pixel diff of the 26 v1 gallery screenshots (390 and 1440) before and after is **0**.

## Step 3: tokens and the Signature preset

- `styles.css` is now an entry file that imports, in order: `tokens.css`, `base.css`,
  `sections/*.css`, `responsive.css`, `presets/classic.css` and `presets/signature.css`.
  - `styles.test.ts` checks that base + sections + responsive equal the pre-v2 stylesheet byte
    for byte (`__snapshots__/styles-v1.css`).
  - `classic.css` adds no rules: classic is the unscoped base, and presets not built yet fall back
    to it.
  - Every Signature selector is scoped to `.ys-site[data-preset='signature']`.
  - v1 pixel diff after the split is still **0** (26 screenshots).
- Tokens (plan 6.2): type steps −1 to 7, label, spacing, section padding, container widths,
  shadows, and a 1 KB inline SVG grain. All are custom properties only.
- Fonts: Cormorant Garamond (roman and italic) and JetBrains Mono are self-hosted with
  `@fontsource-variable`; Inter was already there. All are SIL OFL 1.1 (`packages/sections/FONT_LICENSES.md`).
- Signature:
  - dark surface from `brand.colors.secondary` as stored, with primary and accent glows and grain beside it;
  - hairline glass cards with a solid fallback;
  - mono labels with a 24px leading rule;
  - a glowing pill CTA;
  - a sticky header that turns to glass on scroll (CSS scroll-driven, inside `@supports`, off for
    reduced motion);
  - a CSS-only section rise, also off for reduced motion and when motion is `off`.
- `themeFor()` is surface-aware (plan 6.3), through `surfaceTheme()`:
  - surfaces 0 to 3 are computed from the base;
  - muted text is darkened or lightened until it passes;
  - each brand role is used as text only where it passes 4.5:1 (3:1 for display) on surfaces 0
    to 2, otherwise ink, and those roles are reported in `lowContrast`.
  - Classic output is unchanged.
  - `contrast.test.ts` covers all 16 colour presets and all 10 kit default palettes, on both
    surfaces.
- axe: the schedule "No stop" contrast baseline item is cleared. Signature no longer dims those
  days, and schedules only appear on the Signature kits.
- **Known, by rule:** v1 drafts still on classic keep the old faint "No stop" days, because classic
  must not change. They clear when a site moves to a v2 preset.

## Step 5: never-empty draft preview

- `RenderContext.editing` is true only in the editor canvas. Everywhere else (the draft preview,
  share previews, the live site, exports) `SiteView` renders `withoutPlaceholders(doc)`:
  - every `[[…]]` is removed;
  - list items whose title, name, question or quote was only a placeholder are dropped;
  - rich text loses its empty runs and blocks;
  - sections with nothing to show are left out, so the page's one h1 always lands on a visible section;
  - links to a hidden section go to its page instead.
- Draft preview only: pages with nothing filled in yet leave the menu, and opening one directly
  shows the page title as its h1. Published output is unchanged.
- In the editor, placeholders and "add this" hints are subtle ghost text with a dotted underline
  (`editor.css`, more specific than the original rules, which stay byte for byte).
- "Finish your site" strip in the draft preview banner (`lib/draft/finish.ts`): the top 3 missing
  pieces, in order (menu, weekly stops, 3 photos, services, story, hours, reviews, last
  details). Each links to `/sites/<id>/edit?page=…&section=…`, which opens the editor with that
  section selected and in view.
- Kit headlines: each kit's Home H1 is a default line with an accent phrase (food truck "Street
  food, *made right here.*"). The name stays in the header. Copy improves in D6.
- Each kit's Home also gets a photo strip ("A closer look", up to 6 of the owner's photos, hidden
  under 3).
- Fallback fonts sized to match (Cormorant roman and italic, Inter, JetBrains Mono; local system
  fonts, no download): layout shift on the Signature kits went from 0.059 / 0.010 to **0**.

## Published sites without framework JavaScript (2026-11-27, Clarence's decision)

Published pages (`/_site/<host>/…`) are served by a route handler as plain HTML. The studio and
editor stay on Next.js pages.
- `lib/site/render-entry.tsx` is bundled at build time with its own React
  (`scripts/build-site-renderer.mjs` → `.site-renderer/render.cjs`) and loaded at runtime
  (`lib/site/renderer.ts`), because App Router code may not import `react-dom/server`.
- One first-party stylesheet plus self-hosted fonts, built by `scripts/build-site-css.mjs` into
  `public/_site-assets/` and linked as `site.css?v=<deploy>`.
- Published HTML carries no script except JSON-LD. Forms are plain HTML posts.
- D7 hook: `islands` (first-party, nonce-tagged scripts) is empty for every site today.
- Tests:
  - `tests/unit/published-html.test.ts`: every page of every design fixture, the thank-you page
    and the neutral page;
  - `tests/e2e/published-static.spec.ts`: a real published site, every page, 0 script requests;
    forms submit with JavaScript off.
- `/dev-site` (the harness) uses the same renderer, so Lighthouse measures what visitors get.

**Fonts without layout shift** (decision 2026-11-27):
- Each site preloads its own font pair's Latin files in the page head (`lib/site/font-files.json`), so
  they arrive with the stylesheet and are ready before the first paint: no swap on a normal load.
- Published sites use `font-display: optional`: a font that isn't there in time is not swapped in on
  that page view (the next page has it from cache), so nothing can move on any browser version. The
  studio and editor keep `swap`. Checked: on a normal load every kit draws with its web fonts.
  Trade-off, measured: on a Slow 4G first visit (empty cache) 9 of 10 kits show the size-matched
  fallback on Home; later pages use the cached real fonts. `swap` was tried and failed CI's
  1.5 s delayed-font test on CI's newer Chrome (landlord 0.095, restaurant 0.022). Follow-up PR:
  each site's headline font, subset to that site's characters and sent with the page, so the real
  headline typeface always shows with no swap.
- When a font is still late (slow network), size-matched local fallbacks take the same space
  (`packages/sections/src/fonts.css`): Arial/Times/Courier and their metric twins, then DejaVu; a
  regular face plus bold faces for the 600, 700 and heading-weight bands; widths measured in the
  browser on the sites' own text; digits sized so `ch` widths (`max-width: 62ch`) match too.
- Published fonts are subset at build time to the weights in use; every file of a font declares the
  same weights (a mismatch made browsers skip the Latin file, found and fixed here). The build and
  `tests/unit/site-fonts.test.ts` hold every pair to 100 KB: signature 91.3 KB, classic 70.6,
  editorial 61.7, friendly 34.7, modern 30.8.
- `tests/e2e/font-fallback.spec.ts` lays every rich fixture out with the web fonts (checked loaded)
  and with only the fallbacks: hero within 12%, page within 2% (how close a slow first visit looks;
  exact line breaks differ between browser versions, which is why swaps are off).
- Headlines: display headlines already balance their lines (`text-wrap: balance` in the base styles;
  browsers without it wrap normally). In accented headlines a one- or two-letter word stays with
  the next word (no-break space), so a balanced headline breaks in the same place with either font.
- Slow fonts: `tests/e2e/font-delay.spec.ts` holds every font file back 1.5 s on every rich fixture
  (390 and 1280) and requires the swap's layout shift to stay at or under 0.02. Measured: at most
  0.0008 on any kit at 390, 412 and 1350 wide (trucking was 0.043 before the headline rule).

The CI failures were reproduced locally by hiding the system Inter font (CI machines don't have

## Headline font sent with the page (follow-up to PR 140)

Published sites keep `font-display: optional` (nothing ever moves), and each page now also carries
its own headline typeface inside the HTML, so the brand headline shows even on a slow first visit.
- What: the pair's display font at the headline weight, cut to the characters the site's text uses,
  as a `data:` font in a nonce-tagged `<style>` (family 'YS Headline', applied only to headline
  styles). 6-8 KB per site; Signature 22 KB (with its accent italic). Display-only font files are
  no longer preloaded. `font-src` allows `data:` (the site's own page only).
- When it's made: once per published version, at publish (`goLive` → `warmHeadline`), cached in
  Next's shared data cache under the version id plus a fingerprint of the deployed font files. A page
  view only reads the cache; a fresh server instance reads it too rather than cutting it again. A
  version made live another way (a rollback to one published before this change) is made on its first
  view and cached from then on. Never per page view.
- Proof: `tests/unit/headline-cache.test.ts` (publish makes it; the first and second views and a
  fresh instance cut nothing; only new content makes a new one) and
  `tests/e2e/published-static.spec.ts` (a real published site: first view, repeat view and another
  page all report a cache hit; test-mode-only `x-headline-font` header).
- Production stays clean (`tests/unit/site-route-headers.test.ts`): the published-site route run as
  production (no test mode; and on Vercel even with the test-mode switch set by mistake) sends no
  `x-headline-font` header, the dev-site harness answers 404, and the font-cut counter stays at 0
  (it only counts in test mode).
- Slow 4G first visit, empty cache: the real headline typeface on all 10 kits, every run (body text
  shows the size-matched fallback until the next page). Lighthouse: CLS 0 on all kits; performance
  0.95 (restaurant) to 1.00.

## D2: premium section library (branch `feat/design-d2-sections`)

**New variants:**
- hero: `editorial-split`, `collage`
- about: `chapters`
- menu: `editorial`
- gallery: `mosaic`, `filmstrip`
- testimonials: `big-quote`
- cta_band: `image`
- footer: `statement`

**New section types:**
- `ticker`: a moving strip of 3 to 8 short phrases, with a still, readable list for screen readers and reduced motion.
- `stats`: shows only with 2 or more of the owner's numbers.
- `feature_rows`: alternating photo and text rows.

Each has zod props, a server component, inspector fields and fixture coverage (a "showcase" page in both v2 every-section fixtures). Each reads fully with JavaScript off.

**Layout composer** (`packages/kits/src/composer.ts`) runs on every kit's template and again on the finished draft (`assembleDoc`), so it sees the draft's photos:
- **Home order:** cinematic hero → ticker → feature rows (the kit's own highlights wait in that slot until the owner adds rows) → stats → big quote → mosaic gallery → image call-to-action → statement footer.
- **Rule 1:** no two photo-less sections touch on Home whenever the draft has a photo to use. The composer reorders as little as possible. A text-only about section or hero, or the call-to-action band, may borrow one of the draft's own photos. Other pages keep their kit order and only get a photo where one fits.
- **Rule 2:** at most one full-bleed moment besides the hero on every page, and exactly one on Home when there is a photo.
- **Rule 3:** neighbouring sections alternate surface depth on design-v2 looks (`data-depth="raised"`). Classic markup is unchanged.
- **Nothing invented:**
  - Stats and feature rows start empty.
  - The ticker repeats only the site's own service names.
  - The writer's stats are dropped by the sanitizer.
  - Photos are the owner's, or ones already in the draft.
- **Tests:** `composer.test.ts`, all kits, rich and sparse fixtures (order, rules 1 and 2, nothing invented, composing twice changes nothing).

**Default look** (decision 2026-11-27): Signature for restaurant, food truck and nonprofit; Classic for the rest until D3.

**"Try the new look"** (editor, Edit tab):
- Only on classic sites, and never switched automatically.
- Previewing changes the draft, and the page in the middle shows it at once. The live site changes only on publish.
- "Undo" restores the old look in one click; "Keep the new look" keeps it. Ctrl+Z works too.
- Built on a `set_style` edit that the owner's clicks and undo may send, but the AI's chat edits never can. Brand colors and logo are untouched (R6).

**Accessibility:** the filmstrip is a named, focusable region ("<heading>, photo strip") that scrolls with the arrow keys from the first photo to the last and back. Each photo is announced as "Photo n of N" with its alt text (`tests/e2e/filmstrip.spec.ts`, JavaScript on and off). axe: 44 of 44 fixture pages pass.

**Screenshots:** the design gallery takes every fixture page at 390, 1280 and 1440 (D2 asked for 390 and 1440; the core spec asked for 390 and 1280). CI uploads them as the `design-gallery` artifact. Nothing binary is committed.

**Phone photos:** a full-bleed hero was asking the phone for the 960-wide file, because the next smaller copy is 640. Tree-and-lawn and nonprofit then missed the 0.95 speed budget (0.91 and 0.93, layout shift still 0). Each sample photo now also has an 800-wide WebP, which is the size a phone actually needs. After that, three runs: tree-and-lawn 0.95, nonprofit 0.96–0.97. Accessibility 1 and layout shift 0 on both. Fonts stay under 100 KB per site (signature 91.3 KB).

## D4: imagery engine (branch `feat/design-d4-imagery`, 2026-11-28)

Plan approved by Clarence 2026-11-28: no identifiable faces (hands, people from behind or far away
are fine); images get their own dollar cap inside the overall AI cap, both fail closed, built
switched off; kit library in Supabase storage, kit samples stay the library until the batch script
is run; Meshy and fal left for D7.

**What a new draft gets**
- Imported sites: every photo is checked by pixel analysis (too small, flat graphic, screenshot,
  text-heavy, blurry, blown highlights) and near-duplicates are dropped. The best wide photo
  (1200 px or more, landscape) becomes the Home hero. Kept photos get AVIF and WebP copies, a
  placeholder, a focus point, and the 4:5 phone crop for the hero.
- Library first: the draft opens with library photos at once (kit samples today; the kit library
  once it is made). Nothing waits.
- After the draft is saved, images are made for the business (11-shot list per kit and look, no
  faces, no text, no logos) and each passes the automatic check (pixel check, duplicate check, vision
  check score of at least 0.6, no text, face, logo, warped or off-brief flags) before it replaces a
  library photo. The owner's own photos and anything the owner changed are never replaced.
- Spend: every image and check is priced and logged (`ai_runs.usd`). Images stop, and the library
  stays, when the image cap is reached or spend can't be read.

**How photos render (v2 looks)**
- `<picture>` with AVIF first, then WebP, at several widths; exact width and height; alt text; an
  inline blurred placeholder under the photo; `object-position` from the focus point; the 4:5 crop
  for full-width heroes on phones (kit samples included). Classic keeps its pre-D4 markup byte for byte.
- Grade: one color treatment per look as a CSS filter on photos made for the site and library
  photos (classic has none). The owner's own photos only when they turn on "Photo color" in the
  editor. Brand colors are untouched.
- Asset routes serve copies by name only (`?img=full-640.avif`, strict pattern). Published pages
  read photo details once per published version (cached).

**Kit library**
- `scripts/generate-kit-library.ts`, by hand only. Refuses in CI or Vercel builds, with images off,
  with no image budget, or without `--yes`. A new draft copies the library photos it uses into its
  own tenant (server-side copies).

### D4-1 (Clarence 2026-11-28): display font only from the inline headline font

- Published pages carry the display font only as the inline subset ('YS Headline'). The display
  variable points at it, then the size-matched local fallback, never the web display family, so no
  separate display font file is downloaded on any kit (checked in the Lighthouse reports).
- Each inline face covers every weight (one cut at the display weight, no faux bold). Text in the
  display family at other weights (quotes, initials) now draws at the display weight.
- The cut always includes printable ASCII and common punctuation, so text the page adds itself
  has its glyphs. Inline size per site: 12-13 KB (poster, paper, clean), 28-31 KB (signature,
  craft with italics); was 7-23 KB, while the 20-44 KB display files are no longer fetched.
- Mono label fonts (JetBrains Mono, IBM Plex Mono) are no longer preloaded. They still load for
  labels (font-display: optional, so nothing moves; a slow first visit shows the size-matched
  fallback for labels).
- Before D4-1, four kits were 2.05-2.28 s, limited by font files.
